[Строки для вставки в Excel](../outputs/physical-io-20261001/signals_for_excel.tsv): 133 строки, 7 столбцов с табуляцией, без заголовка; сначала 86 DI, затем 47 DO. Исходный XLSX этой сверкой не перезаписан.

Столбцы: оборудование, сигнал, адрес, назначение, имя в ПЛК, подключение, статус. Имя `GVL_PHYSICAL_IO.<переменная>` используется для I/O Mapping; подключение содержит модуль/CH. Статусы только «есть в ПЛК» и «нету в ПЛК». У фаз MPG A/B пока нет реализации HSC, поэтому их статус — «нету в ПЛК»; остальные 131 BOOL объявлены в PLC.

Три выхода «Авария ячейки в станок» удалены из GVL и каталога. Физическая авария станка приходит от станка; снимает её человек. Локальный Reset сбрасывает наш программный автомат, без физического выхода Reset станка. «ХЗ» и физический ключ SC500 исключены. Старые OPC UA поля `xSc500BenchKeyActive/Lost` остаются FALSE для совместимости.

У операторских дверей станков ручной привод: в NORMAL есть только DI открыто/закрыто, физических DO нет. `FB_MACHINE.xSafetyDoorControlEnabled=FALSE`; HMI показывает статусы, прямой запрос управления дверью отвергается PLC с W10. В SIMULATION и SC500_BENCH управление моделью сохранено.

ГК — отдельный синий конвейер каждого магазина. У каждого свой частотник: DI аварии/работы, DO пуска/сброса и DI детали на конце. У каждого свой `FB_GEOMETRY_CONTROL`: четыре сырых драйверных DI используются технологией без фильтра, DO Run/Reset принадлежат соответствующему FB. В прямом ручном I/O оператор задаёт уровни через отдельный механизм подмены. Оба датчика детали фильтруются в `axGkPartAtEnd[1/2]`: передний фронт по настройке, потеря положения сразу. Запуск после укладки и отхода робота, останов по датчику и изъятие после 3 с непрерывного FALSE — в FB; подробности в [24](24-geometry-control.md).

`xDiMachine1/2/3HatchLocked`: 1 — замок роботного люка заперт, 0 — запирание не подтверждено. Описание «закрыт/открыт» заменено однозначным. НЗ-грибки: физическая 1 означает отжатый грибок, программный `xEmergency*=TRUE` означает нажатие после инверсии. Примечания отделяют штатную логику от прямого ручного I/O: встречные катушки исключаются штатным FB, а ручной слой разрешает отдельные уровни; импульсные команды в нём удерживаются до переключения.

DI16 №5 CH6–15 свободны. CPU DI_CH0/1 зарезервированы под фазы MPG A/B; аппаратный квадратурный счётчик ещё отсутствует. A−/B− — обратные линии дифференциальных пар, отдельные обычные DI для них не выделены. Требуется наладка электрического согласования MPG.

1. Добавить устройства и модули в согласованном порядке, настроить EtherCAT и реальные оси магазинов.
2. В Device → I/O Mapping назначить существующие BOOL `Application.GVL_PHYSICAL_IO.<имя>` на каналы таблицы. При фиксированных адресах проверить адрес корневого канала/модуля и отсутствие пересечений с остальным процессом.
3. Не создавать параллельные AT-переменные: у DO один окончательный писатель — `WritePhysicalOutputs` с завершающим `ApplyIoOutputOverrides`. Комментарии ST и таблица сами не меняют Device Mapping.
4. Проверить обновление входов в задаче, каждую клемму, полярность, пары катушек и требуемые исходные уровни.
5. После проверки выставить `GVL_PHYSICAL_IO.xMappingVerified=TRUE`. Флаг не RETAIN: без него штатный NORMAL не активирует DO и неподменённые фильтрованные DI. Прямая наладочная подмена DI и ручное I/O имеют прежний отдельный контракт, описанный в [23-physical-io-diagnostics.md](23-physical-io-diagnostics.md).

Индексы диагностики независимы от клемм: DI 1–78 сохранены, датчики ГК 79/80, сырые драйверные DI 81–84. DO 1–36 и 40–50 сохраняют прежние имена; удалённые 37–39 не переназначаются. Массивы/маски остаются до индекса 50, каталог содержит 47 выходов. Перед применением новой карты перезапустить приложение PLC с новым кодом и gateway: FIFO неретентный, сохранённые записи SQLite не меняются.

## Гудок, фильтры и Home

`FB_ALARM_HORN` реагирует на новый бит любой из 19 аварийных масок. Удержание/сброс аварии и предупреждения не запускают звук; новая авария перезапускает отсчёт. Длительность фиксируется на начало импульса; 0 выключает звук сразу. Настройка 0–60 с, по умолчанию 2 с. В прямом ручном I/O выбранный DO гудка удерживается независимо от автоматической длительности.

`FB_DI_FILTER` требует непрерывного нового уровня; выбросы не суммируются. `tInputFilterRise/Fall`: 0–5000 мс, по умолчанию 20/20 мс. Опасные спады НЗ-грибков, реле и подтверждений положения проходят сразу; нарастания аварии станка и Стоп — сразу. Фазы MPG и датчики серводрайвера не проходят эти фильтры. Фильтруются 80 технологических DI; четыре драйверных DI ГК остаются сырыми.

Индексы настроек 1–36 сохранены, фильтры 37/38, гудок 39. Gateway передаёт гудок в миллисекундах из секунд HMI. Разрешение смены трёх настроек вычисляет PLC через `xIoFilterSettingsChangeAllowed`: живой HMI, Manual, оборудование остановлено, оси магазинов выключены. Отказ/неверное значение/просрочка — W28, `WARNING`.

Концевики/Home магазинов заведены непосредственно в серводрайверы и не занимают DI MC522. PLC выдаёт `xHome` через осевой FB и `MC_Home`, ждёт Done, Homed и Standstill. Назначение PDO и поиск дома определяются приводом/ESI.

## Проверка и применение

Сверка имён/адресов/модулей, уникальность и ёмкость, исключение удалённых выходов, фильтры, гудок, прямое ручное управление и FIFO проверяются `npm run test:io`. Gateway — `npm run test:gateway`, HMI — `npm run test:ui-state` и `npm run build`. Человеческий каталог: [20-smoke-and-integration-test-catalog.md](20-smoke-and-integration-test-catalog.md).

Для этой сверки обновить GVL_PHYSICAL_IO и методы WritePhysicalOutputs, ApplyIoOutputOverrides, RecordIoDiagnostics. Требования первичного подключения диагностики перечислены в [23-physical-io-diagnostics.md](23-physical-io-diagnostics.md). Бинарный `.project`, сгенерированные XML и рабочий контроллер не изменены.
