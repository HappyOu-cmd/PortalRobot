# Как создать элемент визуализации

## Сначала определить тип элемента

| Задача | Расположение |
| --- | --- |
| Повторно используемая кнопка, индикатор, вкладки, диалог, селект или подсказка | `visu/src/components/ui` |
| Компонент конкретного механизма: станок, робот, магазин | `visu/src/components/<домен>` |
| Экран или компоновка главной сцены | `visu/src/App.tsx` или выделенный экранный компонент |
| Трёхмерный объект или эффект | `visu/src/three` |

Не создавать компонент внутри `App.tsx`, если он используется больше одного раза или имеет собственную логику и стили.

## Общий подход к дизайну

HMI рассчитан на сенсорный экран `1920x1080`. Интерфейс светлый, промышленный и плотный: белые поверхности, серо-синие нейтральные тона, синий для выбранного состояния, зелёный для нормальной работы, оранжевый для ожидания, красный для аварии.

- Использовать существующие CSS-переменные из `visu/src/styles/theme.css` и стили из `visu/src/styles/global.css`.
- Не добавлять градиенты, декоративное свечение, огромные радиусы и карточки без рабочих данных.
- Минимальная цель сенсорного действия: около 44 px. Иконка не должна быть единственным способом понять критичную команду.
- Для новой иконки использовать `@iconify/react` и уже подключённые наборы `@iconify-icons/material-symbols` или `@iconify-icons/mdi`. Перед использованием проверить точный идентификатор иконки.
- Повторно используемые варианты оформлять через `class-variance-authority` и `cn()` из `visu/src/lib/utils.ts`.
- Dialog, Tooltip, Tabs, Select и выпадающие меню строить на Radix UI, но стилизовать CSS проекта.
- Графики статистики строить Recharts, а не вручную рисовать SVG.

## Создание UI-компонента

1. Посмотреть, не покрывает ли задачу `Button`, `CommandButton`, `StatusIndicator`, `Tabs`, `Tooltip`, `Dialog` или `Select` в `visu/src/components/ui`.
2. Создать компонент в соответствующей доменной папке. Передавать данные через типизированные `props`.
3. Добавить короткий Storybook-сценарий `<Компонент>.stories.tsx`: нормальное состояние, disabled, предупреждение и авария, если применимо.
4. Подключить компонент к экрану. Компонент не должен напрямую читать WebSocket, OPC UA или `localStorage`.
5. Запустить Storybook или HMI и проверить все состояния при браузерном масштабе `100%`.

Минимальный каркас:

```tsx
type MachineStateProps = {
  title: string;
  tone: 'neutral' | 'success' | 'warning' | 'danger';
  detail: string;
  onOpen?: () => void;
};

export function MachineState({ title, tone, detail, onOpen }: MachineStateProps) {
  return (
    <button type="button" className={`machine-state machine-state--${tone}`} onClick={onOpen}>
      <span>{title}</span>
      <span>{detail}</span>
    </button>
  );
}
```

## Добавление 3D-элемента

1. Создать или дополнить модуль в `visu/src/three`.
2. Собирать модель из `THREE.Group`, именовать ключевые части и возвращать публичные методы обновления, например `setDoorOpen`, `setActive`, `setPartType`, `update` и `dispose`.
3. Все геометрии, материалы и текстуры освобождать в `dispose()`.
4. В `CellViewport.tsx` создавать объект один раз, а обновлять его состоянием из React. Не пересоздавать Three.js-сцену на каждом рендере.
5. При изменении размеров оборудования пересчитывать опорные точки и пределы перемещения, а не только масштабировать отдельный меш.

Пример публичного контракта:

```ts
type MachineVisual = {
  group: THREE.Group;
  setDoorOpen(open: boolean): void;
  setChuckActive(active: boolean): void;
  setPartType(type: 'blank' | 'detail' | 'empty'): void;
  update(deltaSeconds: number): void;
  dispose(): void;
};
```

## Проверка дизайна

1. При наличии референса сначала сверить размеры, отступы, шрифты, цвета, иконки и активные состояния с ним.
2. Выполнить `npm run build` в папке `visu`.
3. Открыть HMI с масштабом браузера `100%` при `1920x1080`.
4. Проверить клики, touch-цели, disabled-состояния, анимацию открытия и закрытия, отсутствие горизонтальной прокрутки и ошибок консоли.
5. Проверить resize окна: Three.js renderer, камера и подписи оборудования не должны смещаться.
