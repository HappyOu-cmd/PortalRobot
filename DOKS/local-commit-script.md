# Локальный коммит через скрипт

Для повторяющейся синхронизации и локального коммита используются `commit.cmd`
и `tools/commit_project.py`. Требуются Git в PATH и Python 3.10 или новее.
Установка дополнительных Python-пакетов не нужна.

## Запуск через агента

Достаточно запроса:

> Запусти commit.cmd --yes. Комментарий: fix(hmi): сбрасывать сообщение после восстановления OPC UA

Агент запускает из рабочей папки проекта одну команду PowerShell:

```powershell
.\commit.cmd --yes -m "fix(hmi): сбрасывать сообщение после восстановления OPC UA"
```

Скрипт синхронизирует допустимые изменения в соседнюю папку `PortalRobot-GitHub`,
проверяет `git status`, состав индекса и `git diff --cached --check`, создаёт
локальный коммит. В режиме `--yes` вывод короткий: клон, ветка, число выбранных
файлов и SHA. Дополнительного интерактивного подтверждения нет.

Если параллельно делалось несколько задач, агент должен передать известные ему
файлы законченной задачи через повторяющийся `--path`. Папка выбирает всё своё
поддерево. Без `--path` выбираются все допустимые изменения. Разделение разных
задач внутри одного файла выполняется отдельно: скрипт работает с целыми файлами.

```powershell
.\commit.cmd --yes -m "fix(hmi): исправить восстановление связи" --path visu/src/plc/client.ts --path visu/src/App.tsx --path visu/tests/plcConnection.test.mjs --path visu/package.json --path DOKS/20-smoke-and-integration-test-catalog.md
```

Причину, итоговое поведение и уже выполненные проверки можно добавить в тело:

```powershell
.\commit.cmd --yes -m "fix(hmi): исправить восстановление связи" --details "Устраняет залипание сообщения после reconnect. Проверено ранее: npm run test:ui-state, npm run build."
```

Сам скрипт выполняет только Git-проверки. Он явно записывает в тело коммита,
что тесты, сборки, CODESYS и оборудование им не проверялись. Предыдущие проверки
агент указывает в `--details` по их фактическим результатам.

## Предпросмотр и ручной запуск

```powershell
.\commit.cmd --dry-run
.\commit.cmd --dry-run --path visu --path DOKS
```

Предпросмотр показывает состав без копирования файлов, staging и изменения HEAD.
При запуске `commit.cmd` без аргументов доступны выбор номеров файлов, ввод
заголовка и просмотр полного diff перед окончательным подтверждением.

Заголовок имеет вид `type(scope): описание`. Типы: `fix`, `feat`, `refactor`,
`docs`, `test`, `chore`. Примеры областей: `plc`, `gateway`, `hmi`, `cell`, `tools`.

## Состав и сохранность изменений

Обычный состав: ST-исходники `Portal_robot`, HMI, gateway, конфигурация сборки,
пакетные манифесты, ресурсы HMI, тесты, документация, исходники симулятора и tools.
Корневые `commit.cmd`, `verify.cmd`, README и изображения внутри DOKS также входят.

Отсеиваются `AGENTS.md`, `node_modules`, `dist`, артефакты сборки, виртуальные
окружения, кеши, логи, базы SQLite, сертификаты, закрытые ключи, рабочие `.env`,
локальные конфигурации и `visu/gateway/data`. Дополнительно учитывается `.gitignore`
клона. Шаблоны `.env.example`, `.env.sample`, `.env.template` допустимы.

Снимок `Portal_robot.project` и XML-экспорты добавляются отдельным параметром:

```powershell
.\commit.cmd --yes --include-codesys -m "chore(plc): сохранить проект и экспорты"
```

Копирование снимка и экспортов побайтовое; их содержимое не редактируется.
Владельцем актуальности сохранённого проекта остаётся пользователь.

Отсутствующие в рабочей папке файлы клона сохраняются, включая README и
документацию, существующую только в клоне. Удаление указывается явно для каждого
файла, уже удалённого из исходников:

```powershell
.\commit.cmd --yes -m "refactor(hmi): удалить старый эффект" --delete visu/src/three/OldEffect.ts
```

При чужой отличающейся незакоммиченной правке того же файла, непустом индексе,
merge/rebase, неверном origin, выходе пути за корень, изменении выбранных файлов
или HEAD после предпросмотра скрипт останавливается. Несвязанные незакоммиченные
правки в клоне сохраняются. Уже синхронизированный файл, совпадающий с исходником,
можно закоммитить повторным запуском, если индекс пуст.

При ошибке после копирования файлы могут остаться синхронизированными и staged.
Автоматического отката нет: точное состояние доступно через `git status` в клоне.
При ошибке commit-hook HEAD остаётся прежним, выбранные правки сохраняются.

Публикация в удалённый репозиторий выполняется отдельным явным запросом.
Обычный запуск сохраняет версии, `VERSION`, `CHANGELOG.md` и теги выпусков.

## Проверка инструмента

```powershell
python -B -m unittest discover -s tools/tests -v
```

Все проверки создают отдельные временные Git-репозитории: успешный коммит с
переданным комментарием без вопросов, выбор файлов, предпросмотр, исключения,
сохранение чужих правок и README, ошибки индекса/merge, конкурентные изменения,
снимки CODESYS, явные удаления, Git-ignore, CRLF, отказ commit-hook и проверка путей.
Рабочий Git-клон, PLC и журнал событий в этих тестах не используются.
