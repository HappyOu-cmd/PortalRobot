# Карта Modbus TCP для внешнего робота SC-500

## Статус документа

PLC работает как Modbus TCP Client, робот — как Server. Реализованный проектный
контракт `1001–1117` должен быть реализован в программе робота и проверен на
реальном SC-500. Справочная карта `1–117` взята из документа Huacheng для
контроллера литьевого робота и **не подтверждена для INOVANCE SC-500**.

Документные адреса однобазные: адресу `1001` соответствует
`uiStartItem := 1000` в `ModbusFB`.

## Проектная карта: PLC → робот

| Адрес | Имя | Формат | Назначение |
| ---: | --- | --- | --- |
| 1001 | `CommandCode` | UINT | Код технологической команды |
| 1002 | `Execute` | BOOL 0/1 | Запрос выполнения команды |
| 1003 | `Stop` | BOOL 0/1 | Приоритетная контролируемая остановка |
| 1004 | `Reset` | BOOL 0/1 | Сброс ошибки контроллера робота |
| 1005 | `ActiveSlot` | UINT | Единственный слот текущей магазинной команды; 0 вне магазина |
| 1006 | `MagazineId` | UINT | `1` или `2` для магазинной команды; `0` вне магазина |
| 1007 | `Reserved` | UINT | Зарезервировано; PLC записывает 0 |
| 1008 | `CommandSeq` | UINT | Номер транзакции; 0 зарезервирован |
| 1009 | `PlcHeartbeat` | UINT | Циклический счётчик жизнеспособности PLC |

### Коды `CommandCode`

| Код | Команда |
| ---: | --- |
| 0 | `NONE` |
| 1 | Зарезервирован; робот должен вернуть `unsupported command` |
| 2 / 3 | `GRIPPER_1_OPEN` / `GRIPPER_1_CLOSE` |
| 4 / 5 | `GRIPPER_2_OPEN` / `GRIPPER_2_CLOSE` |
| 6 / 7 | `ROTATE_TO_BLANK` / `ROTATE_TO_DETAIL` |
| 10–13 | `MACHINE_1_ABOVE`, `INSIDE`, `CHUCK_APROACH`, `CHUCK_POSITION` |
| 14–17 | Аналогичные четыре точки станка 2 |
| 18–21 | Аналогичные четыре точки станка 3 |
| 22 | `HOME_SAFETY` |
| 23 | `MAGAZINE_SAFE` — безопасная высота над `ActiveSlot` |
| 24 | `MAGAZINE_CHANGE` — высота смены захвата над `ActiveSlot` |
| 25 | `MAGAZINE_IN_SLOT` — рабочая точка внутри `ActiveSlot` |

`MAGAZINE_TAKE_DETAIL`, `PUT_DETAIL`, `CHANGE_DETAIL` и `RETURN_BLANK` не являются
командами Modbus. Их пошагово выполняет `FB_MAGAZINE` одинаково для SoftMotion и
Modbus, используя только элементарные коды выше.
Для кодов `23–25` робот принимает только `MagazineId=1/2` и `ActiveSlot=1..120`;
остальные сочетания отклоняются без движения.

## Проектная карта: робот → PLC

| Адрес | Имя | Формат | Назначение |
| ---: | --- | --- | --- |
| 1101 | `AckSeq` | UINT | Номер принятой транзакции |
| 1102 | `ExecutionState` | UINT | Состояние исполнения команды |
| 1103 | `ResultCode` | UINT | Результат команды; 0 — ошибки нет |
| 1104 | `ActiveCommand` | UINT | Фактически выполняемая команда |
| 1105 | `CurrentPoint` | UINT | Последняя подтверждённая точка; один из кодов движения `10–25` |
| 1106 | `GripperStatus` | bit mask | Обратная связь захватов и переворота |
| 1107 | `RobotHeartbeat` | UINT | Циклический счётчик робота |
| 1108 | `RobotStatusWord` | bit mask | Состояние контроллера и готовность |
| 1109 | `ActiveAlarmCode` | UINT | Номер активной аварии; 0 — аварии нет |
| 1110–1111 | `ActualX` | signed DINT | X × 0,1 мм, старшее WORD первым |
| 1112–1113 | `ActualY` | signed DINT | Y × 0,1 мм, старшее WORD первым |
| 1114–1115 | `ActualZ` | signed DINT | Z × 0,1 мм, старшее WORD первым |
| 1116 | `OperationPhase` | UINT | Диагностическая фаза алгоритма робота |
| 1117 | `ProtocolVersion` | UINT | Версия контракта; текущая версия 3 |

`ExecutionState`: `0 IDLE`, `1 ACCEPTED`, `2 BUSY`, `3 DONE`, `4 ERROR`,
`5 STOPPED`.

`OperationPhase`: `0 IDLE`, `10 VALIDATING`, `20 ACCELERATING`, `30 MOVING`,
`40 DECELERATING`, `50 GRIPPER`, `60 ROTATING`, `90 STOPPING`, `100 FAULT`.
Это диагностическая детализация `BUSY/ERROR`; управляющие переходы PLC от неё
не зависят.

`ResultCode`: `0 OK`, `1 unsupported command`, `2 invalid point`,
`3 invalid slot`, `4 not ready`, `5 safety interlock`, `6 motion error`,
`7 gripper error`, `8 stopped`, `255 internal error`.

`GripperStatus`: bit 0 — захват 1 открыт; bit 1 — закрыт; bit 2 — захват 2
открыт; bit 3 — закрыт; bit 4 — повёрнут к заготовке; bit 5 — повёрнут к
готовой детали. Одновременные Open и Closed одного захвата недопустимы.

`RobotStatusWord`: bit 0 — контроллер включён; bit 1 — Auto; bit 2 — Remote;
bit 3 — приводы включены; bit 4 — Homed; bit 5 — E-Stop; bit 6 — Alarm;
bit 7 — Ready; bit 8 — координаты достоверны; bit 9 (`0x0200`) —
`SimulatorActive`, устанавливается только Python-симулятором для тестовой среды.
Реальный SC-500 обязан оставлять bit 9 сброшенным.

Python-симулятор использует тестовые `ActiveAlarmCode`: `100 E-Stop`,
`101 motion`, `102/103 gripper 1/2`, `104 safety`, `105 homing lost`,
`106 drives disabled`, `107 PLC heartbeat lost`, `108 external Stop`,
`109 forbidden mode change`. Это диагностические коды симулятора, а не
подтверждённый каталог аварий SC-500.

## Как управлять регистрами

- PLC пишет весь блок `1001–1009` одной FC16, чтобы команда, `MagazineId` и `ActiveSlot` были согласованы.
- Для новой команды PLC увеличивает `CommandSeq`, записывает аргументы и устанавливает `Execute=1`.
- Робот копирует номер в `AckSeq`, проходит `ACCEPTED → BUSY → DONE/ERROR` и удерживает итог до снятия Execute.
- После приёма нового `CommandSeq` спад `Execute` не отменяет выполнение: он
  только подтверждает получение PLC терминального результата. Повтор той же
  технологической команды всегда получает новый `CommandSeq`.
- После подтверждения PLC снимает Execute и очищает команду; робот возвращается в `IDLE`.
- `Stop` и `Reset` обрабатываются приоритетно; перед `Reset=1` PLC снимает
  `Execute/Stop` и очищает команду, а включение приводов через этот контракт не выполняется.
- Stop движения выполняет контролируемое торможение. Stop захвата или переворота
  сначала завершает начатое дискретное действие. Затем робот выдаёт
  `STOPPED + ResultCode 8`, фиксирует аварию и ждёт снятия Execute/Stop и Reset.
- После запуска и reconnect PLC сначала читает `AckSeq`, записывает очищенный блок и не повторяет старую команду.
- PLC считает связь живой только при успешном FC03, совпадении версии протокола и изменении heartbeat.

## Алгоритмы магазина

- `TAKE`: установить `ActiveSlot=TakeSlot`, затем `ROTATE_TO_DETAIL → MAGAZINE_SAFE → MAGAZINE_IN_SLOT → GRIPPER_1_CLOSE → MAGAZINE_SAFE`.
- `PUT`: установить `ActiveSlot=PutSlot`, затем `ROTATE_TO_BLANK → MAGAZINE_SAFE → MAGAZINE_IN_SLOT → GRIPPER_2_OPEN → MAGAZINE_SAFE`.
- `CHANGE`: `ActiveSlot=PutSlot`, затем `ROTATE_TO_BLANK → MAGAZINE_SAFE → MAGAZINE_IN_SLOT → GRIPPER_2_OPEN → MAGAZINE_CHANGE → ROTATE_TO_DETAIL`; установить `ActiveSlot=TakeSlot`, затем `MAGAZINE_CHANGE → MAGAZINE_IN_SLOT → GRIPPER_1_CLOSE → MAGAZINE_SAFE`.
- `RETURN_BLANK`: установить `ActiveSlot=PutSlot`, затем `ROTATE_TO_DETAIL → MAGAZINE_SAFE → MAGAZINE_IN_SLOT → GRIPPER_1_OPEN → MAGAZINE_SAFE`.

Матрица меняется только после `DONE` всей операции. При `Stop` или `Error`
содержимое слотов автоматически не корректируется.

аварии, но исходная страница этого явно не утверждает. До проверки SC-500
проектная логика использует собственный регистр `1109`, где `0` определён как
«аварии нет».

## Проверка первого подключения

1. Проверить, что документный `1101` читается через PDU offset `1100`.
2. Проверить FC03 `1101–1117`, FC16 `1001–1009` и Unit ID.
3. Проверить порядок WORD и знак координат на положительной и отрицательной позиции.
4. Убедиться, что heartbeat меняется, версия равна 3, Ready формируется из реальных условий.
5. Проверить Stop и Reset, затем захваты и перемещения, затем операции магазина.

До появления реального контроллера этот контракт реализован в
[`robot_simulator`](../robot_simulator/README.md). Симулятор является тестовой
моделью, а не подтверждением фактических возможностей SC-500.
