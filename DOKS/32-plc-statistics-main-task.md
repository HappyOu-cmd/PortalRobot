# Оперативная статистика PLC в MainTask

Изменение от 02.11.2026. Один экземпляр `PLC_PRG.STATISTIC_MAIN` собирает время
каждый скан и пересчитывает четыре процента загрузки и семь средних раз в 100 мс.
Отдельная задача статистики не требуется.

## Исполнение

`RunStatistics()` вызывается после `RunRobot()`, до `RunAlarms()` и `PublishHmi()`.
На каждом скане фиксируются состояния и накапливается прошедшее время. Деление
выполняется после накопления 100 мс реального времени; при MainTask 4 мс — раз
на 25 сканов. При джиттере расчёт выполняется в первом скане после достижения
100 мс, без повторных вычислений для «догоняния».

`RunStatistics` — единственный писатель `GVL_STATISTIC.stStatistic`. Публикация
происходит по `xUpdated`: после расчёта либо сразу при новом Start. Старая
программа `STATISTIC` оставлена пустой для совместимости с Task Configuration;
она не создаёт FB и не пишет данные. Межзадачных буферов и ожиданий нет.

- Состояние операции должно быть видно хотя бы в одном скане MainTask.
  Несколько коротких операций между расчётами учитываются раздельно.
  Средние используют только завершённые интервалы; загрузка включает текущий.
- Первый скан и фронт `GVL_CELL_MANAGER.Status.xRunning` обнуляют сессию.
  Удерживаемый TRUE не сбрасывает её повторно. Уже активная операция начинает
  новый измеряемый интервал в момент сброса. Само снятие Running, как и прежде,
  не сбрасывает данные и не останавливает учёт видимых состояний.
- Интервал относится к состоянию и коэффициенту прошлого скана. Ускорение
  ограничено 1..250 и применяется к отдельным интервалам, без пересчёта прошлого.
  Период расчёта 100 мс остаётся реальным и не ускоряется вместе с симуляцией.
- Одно чтение TIME() передаётся через `udiNowMs`. Разность учитывает переполнение
  32-битных часов при непрерывном сканировании. Накопители и счётчики — ULINT;
  публикуемый TIME сохранён и насыщается до 4294967295 мс вместо оборачивания.

Каналы 1..4: CycleActive станков 1–3 и Busy робота. Каналы 5..11: Busy станков
1–3, движения к MACHINE_1/2/3_ABOVE и общий Busy двух магазинов. Имена полей
ST_STATISTIC, GVL_STATISTIC и GVL_HMI сохранены. Сменная статистика gateway/
SQLite не меняется.

## Применение в CODESYS

1. Создать DUT `ST_STATISTIC_SAMPLE` из `ST/ST_STATISTIC/ST_STATISTIC_SAMPLE.st`.
2. Обновить декларации и реализации `FB_CALCULATE`, затем `FB_STATISTIC` из
   `FB/FB_STATISTIC`. Внутренний интерфейс FB_CALCULATE изменён; его единственный
   вызывающий блок — обновлённый FB_STATISTIC.
3. В PLC_PRG добавить `STATISTIC_MAIN : FB_STATISTIC`, создать private-метод
   `RunStatistics` из `PLC_PRG.RunStatistics.st` и добавить один вызов после
   `RunRobot()`. В ST-исходниках это уже сделано.
4. Обновить STATISTIC её пустой совместимой реализацией. Удалить вызов программы
   из StatisticTask, затем удалить отдельную задачу. Создавать задачу на 100 мс
   не нужно: интервал обеспечивает FB в MainTask.
5. Состав GVL_STATISTIC прежний; обновлён только комментарий владельца.
   MainTask и SoftMotion оставить с прежними периодами и приоритетами.
6. Самостоятельно скомпилировать, сохранить и загрузить проект. Сравнить среднее/
   максимальное время MainTask, джиттер и CPU до/после на одинаковом автоцикле.

`.project`, Task Configuration XML и сгенерированные экспорты вручную не менялись.

## Локальные проверки

`robot_simulator/tests/test_plc_statistics.py` исполняет фактические ST-блоки
и RunStatistics в ограниченном исполнителе. Часы и внешние состояния задаются
тестом, подключение к PLC и движение не выполняются.

| Случай | Вход | Ожидаемый результат |
| --- | --- | --- |
| Один скан | Busy на 4 мс между расчётами | Одна операция, среднее 4 мс |
| Несколько операций | Интервалы 4 и 8 мс | Две операции, среднее 6 мс |
| Семь средних | По одному 12-мс интервалу каждого назначения | Обновляется соответствующее прежнее поле |
| Незавершённая операция | Busy активен на расчёте, затем снят | Загрузка учитывает текущий интервал, среднее — только завершённый |
| Новый Start | Старое среднее, фронт Running при Busy | Немедленный сброс, новый интервал от Start; TRUE повторно не сбрасывает |
| Переполнение TIME | Интервал через 2³² мс | Длительность и период расчёта сохранены |
| Ускорение | Коэффициенты 0/1/2/250/999 | Ограничение 1..250; среднее масштабируется, расчёт остаётся 100 мс |
| Смена ускорения | Часть операции при 2, часть при 5 | Сумма фактически масштабированных интервалов |
| Граница UINT | Завершение операции №65536 | Счётчик и среднее корректны |
| Длинная сессия | Время больше полного диапазона TIME | ULINT не оборачивается, загрузка корректна |
| Граница результата TIME | Среднее больше диапазона TIME | Насыщение; проценты ограничены 0..100 |
| Интеграция | Busy второго магазина и вызов старой STATISTIC | Публикация через MainTask, старая программа ничего не меняет |

Из robot_simulator: `.\.venv\Scripts\python.exe -B -m pytest -q tests/test_plc_statistics.py`.

Компиляция CODESYS, визуальная проверка и фактическая экономия CPU не проверены.
