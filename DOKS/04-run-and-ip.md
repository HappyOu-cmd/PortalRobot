# Запуск проекта и изменение IP

## Что требуется

- Node.js 20+ и npm для HMI/gateway;
- CODESYS Runtime или PLC с запущенным OPC UA server;
- Chromium-браузер для проверки HMI.

Зависимости восстанавливаются из `visu/package-lock.json`; чужую папку
`node_modules` не копировать.

## Первый запуск

```powershell
cd 'C:\Users\KOKSHAROV IR\Desktop\Project\Portal robot\visu'
npm install
npm run dev:live
```

`dev:live` запускает gateway и Vite. По умолчанию:

- HMI: `http://127.0.0.1:5173/`;
- gateway health: `http://127.0.0.1:3001/api/health`;
- WebSocket: `ws://127.0.0.1:3001/ws`.

Для отдельной проверки компонентов использовать `npm run storybook` и порт
`6006`. Production-проверка: `npm run build`.

## IP PLC

Перед запуском gateway задать endpoint в текущем окне PowerShell:

```powershell
$env:OPCUA_ENDPOINT = 'opc.tcp://192.168.0.181:4840'
$env:OPCUA_GVL = 'GVL_HMI'
$env:GATEWAY_PORT = '3001'
npm run gateway
```

Заменить `192.168.0.181` на фактический IP PLC. Для Runtime на этом компьютере
использовать `opc.tcp://127.0.0.1:4840`. Переменная действует только в текущем
окне; после изменения перезапустить gateway.

## Логин и пароль OPC UA

Для входа gateway использует учётную запись самого PLC. Учётные записи
веб-интерфейса HMI на OPC UA server не передаются.

Перед запуском задать `OPCUA_USERNAME` и `OPCUA_PASSWORD` в текущем PowerShell.
Пароль вводится в локальном диалоге, не записывается в исходники и историю команд:

```powershell
cd 'C:\Users\KOKSHAROV IR\Desktop\Project\Portal robot\visu'
$env:OPCUA_ENDPOINT = 'opc.tcp://192.168.20.80:4840'
$plcLogin = Get-Credential -Message 'Учётная запись PLC для OPC UA'
$env:OPCUA_USERNAME = $plcLogin.UserName
$env:OPCUA_PASSWORD = $plcLogin.GetNetworkCredential().Password
try { npm run dev:live }
finally {
    Remove-Item Env:OPCUA_USERNAME, Env:OPCUA_PASSWORD -ErrorAction SilentlyContinue
    $plcLogin = $null
}
```

Остановить предыдущий `dev:live` через Ctrl+C перед запуском. Основное подключение
и отдельная сессия диагностики используют одинаковые данные PLC при каждом
переподключении. В журнале запуска виден только тип входа `UserName`/`Anonymous`.
Без обеих переменных сохраняется Anonymous; если задана только одна, запуск
останавливается с ошибкой конфигурации. После отказа пароля перехода на Anonymous нет.

На PLC оставить `CmpOPCUAServer → UserAuthentication = ENABLED` и предоставить
группе выбранного пользователя доступ к `RemoteConnections → OPCUAServer` и
нужному набору символов. Сервер должен объявлять токен `UserName` для выбранного
endpoint. Ошибка `Cannot find USERNAME user token policy in end point description`
возникает до проверки пароля и означает отсутствие такого токена.

Текущие настройки gateway используют канал `None/None`. Если сервер передаёт
сертификат и объявляет шифрование пользовательского токена, `node-opcua` шифрует
пароль по этой политике. Если сервер не передаёт сертификат, для диагностического
входа потребуется `AllowUserPasswordOnPlaintext = YES` на PLC, OK и перезапуск
Runtime. В этом случае пароль передаётся открытым текстом; такой вариант применять
только для проверки в доверенной локальной сети. После проверки создать сертификат
OPC UA server на PLC и вернуть запрет передачи паролей открытым текстом.
Сертификат сервера PLC и сертификат клиента gateway — разные файлы.

Настройки: [официальная документация CODESYS](https://content.helpme-codesys.com/en/CODESYS%20Communication/_comm_dlg_device_security_settings.html).

## Сертификат OPC UA gateway

Основное подключение и отдельная сессия диагностики используют один
`applicationUri`: `urn:<имя-компьютера>:PortalRobotHmiGateway`. Отображаемое имя
приложения — `Portal Robot HMI Gateway`.

Gateway дожидается инициализации общего закрытого ключа до запуска двух сессий,
чтобы первое подключение не зависело от порядка их выполнения.

При первом подключении `node-opcua` создаёт сертификат и закрытый ключ в
`visu/gateway/data/opcua-pki/<имя-компьютера>/`. Сертификат находится в
`own/certs/client_certificate.pem`; его URI в `subjectAltName` совпадает с
`applicationUri`. При повторных запусках используются те же файлы. На другом
компьютере выбирается отдельный каталог по имени хоста. PKI входит в
игнорируемый `gateway/data` и в Git не переносится.

Предупреждение `NODE-OPCUA-W06` означает несовпадение URI сертификата и клиента.
После обновления этой настройки нужно перезапустить gateway; общий сертификат
`NodeOPCUA-Client` из AppData больше не используется. Если на контроллере
включена проверка клиентских сертификатов, новый сертификат gateway нужно
добавить в доверенные через штатные настройки контроллера.

Разрешение анонимного входа на OPC UA server настраивается отдельно:
эта правка сертификата не устраняет ошибку
`Cannot find ANONYMOUS user token policy in end point description`.

## IP веб-интерфейса и доступ с панели

На компьютере HMI запускать Vite с внешним bind:

```powershell
npm run dev:live
```

Открывать с панели `http://<IP-компьютера-HMI>:5173/`. Если gateway находится
на другой машине, перед запуском Vite задать:

```powershell
$env:VITE_GATEWAY_URL = 'ws://<IP-компьютера-gateway>:3001/ws'
npm run dev:web
```

В режиме разработки достаточно разрешить входящий TCP-порт `5173`: Vite
проксирует к локальному gateway и REST, и WebSocket основного HMI. Порт `3001`
нужен только для прямого доступа к gateway в production. Не добавлять локальные
IP и секреты в Git.

## Мобильный доступ: редактор точек и JOG-пульт

Телефон и компьютер HMI должны находиться в одной доверенной сети. Сначала на
основном экране ячейки выполнить обычный вход и оставить HMI открытым: мобильный
вход разрешён только под тем же аккаунтом и только пока его основная сессия
активна.

Текущий аккаунт для телефона определяется последним успешным входом на основном
HMI. Другие открытые вкладки и старые административные сессии не меняют этот
выбор. После выхода текущего пользователя либо потери его HMI-соединения
мобильный доступ закрывается; более старая вкладка автоматически не становится
основной. При смене аккаунта старая мобильная сессия завершается, телефон сам
обновляет имя пользователя и предлагает войти заново. Перезапуск gateway для
перелогина не нужен.

Для проверки в режиме разработки открыть с телефона:

```text
http://<IP-компьютера-HMI>:5173/mobile
```

Для проверки production-сборки выполнить `npm run build`, запустить gateway на
нужном сетевом интерфейсе и открыть порт `3001`:

```powershell
$env:GATEWAY_HOST = '<IP-компьютера-HMI>'
npm start
```

Затем открыть `http://<IP-компьютера-HMI>:3001/mobile`. Не привязывать gateway к
`0.0.0.0` в недоверенной или общей сети: мобильный маршрут управляет реальным
движением робота. На телефоне сервер принудительно оставляет только специальный
мобильный API: редактор точек и ограниченный пульт непрерывного/шагового JOG.
Обычные API и WebSocket полного HMI блокируются. Скорость мобильного JOG не может
превысить глобальный параметр «Скорость проверки» (`rPointCheckSpeedPercent`),
который PLC также применяет к проверке сохранённых точек.

### Проверка точки с удержанием

«Проверить точку» открывает окно с сохранёнными координатами и скоростью.
Само открытие окна не запускает движение. Нажать и удерживать площадку
«Удерживайте для движения»; отпускание, отмена касания, закрытие окна, потеря
фокуса или сворачивание страницы прекращают
подтверждение удержания и отправляют Stop. После отпускания нужно дождаться
фактического останова. Для продолжения требуется новое нажатие, автоматического
возобновления нет. Экранное удержание не заменяет аппаратные средства безопасности.

Gateway выдаёт одноразовый `holdId` (`prepareCheck`). Запуск `check` и обновления
`holdCheck` связаны с ним; отпускание отменяет id даже при опережении запроса
запуска. Подтверждения отправляются каждые 300 мс. Через 1500 мс без свежего
удержания gateway запрашивает Stop; отдельный watchdog PLC остаётся равен 2 с.
Обычный опрос `/state` не обновляет heartbeat проверки. Stop не ждёт подтверждения
запуска и повторяется до терминального состояния, чтобы поздний CommandSeq не
запустил уже отменённую проверку.

Окончание определяется в PLC по подтверждению Motion нужной точки и фактическому
завершению движения. `uiPointCheckState = 2` и `xPointCheckActive = FALSE` относятся
к `udiPointCheckRunSeq` запущенной проверки. HMI не подменяет это сравнением XYZ.
При обновлении версии с удержанием нужно загрузить изменённые `PLC_PRG.st` и
`PLC_PRG.RunRobot.st` через CODESYS, перезапустить `npm run dev:live` и обновить
страницу телефона. Команды сборки/загрузки PLC выполняет наладчик.

Мобильная страница прокручивается независимо от запрета прокрутки настольной
3D-сцены. Высота диалога использует `dvh`, снизу учтён `safe-area-inset-bottom`.
У сенсорных кнопок и вложенных подписей отключены выделение, touch-callout и
жесты увеличения; поля ввода остаются редактируемыми. Поведение CSS сверено с
[документацией Safari](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariCSSRef/Articles/StandardCSSProperties.html)
и [описанием safe area WebKit](https://webkit.org/blog/7929/designing-websites-for-iphone-x/).

## Проверка связи

1. В `/api/health` проверить `status: connected` и пустой `missing` для
   обязательных символов.
2. В HMI дождаться смены «Нет связи» на рабочий статус.
3. Если символ отсутствует, проверить опубликованный `GVL_HMI`, endpoint PLC,
   загрузку программы и перезапустить gateway.
4. `ERR_CONNECTION_REFUSED` на `5173` означает, что Vite не запущен или порт
   заблокирован; отказ на `3001` — аналогично для gateway.
