# OPC UA: тег из PLC и привязка к визуализации

Документ начинается с уже созданного и опубликованного поля в `GVL_HMI`.
Настройка самого поля в CODESYS здесь не описывается. Визуализация получает
данные только через gateway.

## Поток данных

```text
GVL_HMI.<поле>
  -> OPC UA server
  -> visu/gateway/server.mjs
  -> WebSocket snapshot
  -> visu/src/plc/client.ts
  -> model/types.ts и CellState
  -> React-компонент или Three.js
```

Координаты робота `lrActualX/Y/Z` gateway собирает из последнего состояния OPC UA
в один `robotFrame` с локальными `sequence`, нормализованным временем и исходным
`sourceTimestampMs`. Three.js хранит эти
кадры и воспроизводит положение портала с фиксированным отставанием 250 мс,
интерполируя только между полученными координатами. После интерполяции применяется
критически затухающий фильтр положения с запретом перелёта через текущую цель.
Числовые координаты HMI, аварии и технологические состояния остаются без этой
визуальной задержки.

## Новый статус от PLC

1. Записать точный путь символа, например `stMagazineStatus.xReady` или
   `astMachineStatus[1].xProcessing`. Имя в gateway, клиенте и модели должно
   совпадать с опубликованным путем.
2. Если отсутствие тега делает экран неполным, добавить путь в
   `requiredSymbols` файла `visu/gateway/server.mjs`. Не добавлять туда каждый
   необязательный показатель.
3. Добавить поле в подходящий тип `visu/src/model/types.ts` и нейтральное значение
   в `src/model/defaults.ts`/`scenarios.ts`.
4. В `mapPlcSnapshot()` или `mapRuntimeInfo()` файла `src/plc/client.ts` прочитать
   путь из `values`, преобразовать его (`booleanValue`, `numberValue`, текст
   состояния) и сохранить fallback из текущего состояния.
5. Передать новое поле в компонент через `props`. Компонент не получает NodeId и
   не читает `values` напрямую.
6. Для offline/degraded режима показать нейтральное состояние, а не выдавать
   устаревшее значение за подтверждённое PLC.

## Привязка к новому элементу

```tsx
<StatusIndicator
  active={state.magazineState.ready}
  label={state.magazineState.ready ? 'Готов' : 'Не готов'}
/>
```

Если данные относятся к повторяемой сущности, передавать их из массива по
индексу (`machines[index]`), а не дублировать отдельные поля для каждого станка.
Для 3D передавать тот же `CellState` в `CellViewport`; синхронизацию выполняет
`cellScene`.

## Если элемент отправляет команду

1. Команда должна быть явно добавлена в `commandMap` gateway с разрешённым путем,
   типом и `pulse: true` для одноразового импульса либо иметь отдельный обработчик
   подтверждаемой транзакции, как `cell.manual` и редактор точек.
2. React вызывает существующий клиент: `plcClient.send({ command: 'area.action' })`.
   Браузер не передаёт произвольный NodeId или путь OPC UA.
3. Результат подтверждать новым статусом из PLC, а не только фактом нажатия.
   При отказе показывать сообщение gateway/PLC и сохранять disabled-условия.

## Подтверждаемое переключение режима ячейки

Команда браузера остаётся `cell.manual` с Boolean `value`. Напрямую писать
`xCellManual` нельзя: это read-only фактический режим PLC.

| Тег GVL_HMI | Владелец записи | Назначение |
| --- | --- | --- |
| `xCellManualRequest` | Gateway | Требуемый режим; записывается первым |
| `udiCellModeCommandSeq` | Gateway | Новый ненулевой номер; фиксирует готовый запрос |
| `udiCellModeAckSeq` | PLC | Последняя обработанная команда, включая отказ |
| `uiCellModeResult` | PLC | 1 применено; 2 ручной режим запрещён работающим циклом; 3 автомат запрещён общей аварией |
| `xCellManual` | PLC | Фактический режим, из него HMI получает `manualMode` |

Gateway сериализует запись буфера до соответствующего AckSeq. При отказе или
таймауте сообщает ошибку, при незавершённой транзакции не перезаписывает запрос.
Повторной отправки и fallback на старый тег нет. При отсутствии новых символов
нужно обновить PLC и публикацию символов, затем перезапустить gateway.

Успешная OPC-запись любой команды подтверждает доставку, но не применение.
`writeValue` не меняет `latestValues` и не публикует отправленное значение как
телеметрию. Изменение интерфейса определяется чтением и подпиской PLC.

## Инженерные таймауты

Экран `Инженерные параметры -> Таймауты` использует один подтверждаемый канал
`uiCellSettingIndex/lrCellSettingRequest/udiCellSettingCommandSeq`. PLC публикует
применённые значения отдельно и принимает изменения только при остановленных
ячейке, роботе, осях и транзакции Dynamic Limits. В меню входят:

- девять технологических ожиданий `FB_MACHINE`;
- общий профиль `FB_AXIS` для X/Y/Z и отдельный профиль `FB_AXIS_GROUP`;
- динамика SoftMotion: глобальные проценты разгона, торможения и jerk, а также
  абсолютные `HaltDeceleration` и `HaltJerk` группы XYZ;
- старт проверки точки, транзакция Dynamic Limits, watchdog HMI, мобильного
  движения и проверки точки, срок действия подтверждаемой команды;
- в разделе Modbus — таймаут ответа, heartbeat, старта и полного выполнения
  команды внешнего робота. Таймауты старта и выполнения хранятся в RETAIN.

Периоды опроса, мигание лампы, длительность импульса сброса, антидребезг,
выдержки внутренних состояний и времена симуляции не являются таймаутами отказа
и в этот экран не входят.

## Подтверждаемые разовые команды и настройки — 16.09.2026

Gateway больше не формирует сетевые импульсы TRUE/150 мс/FALSE. Каждому из
121 разовых сигналов назначен неизменный номер в `visu/gateway/command-contract.mjs`;
PLC-сопоставление находится в `PLC_PRG.ReadHmiCommands.st`.
Новые номера добавляются в конец; существующие нельзя переставлять.

- `audiHmiCommandSeq[1..121]` и `audiHmiCommandIssuedAtMs[1..121]` пишет только gateway.
- `audiHmiCommandAckSeq` и `auiHmiCommandResult` пишет только PLC. Result=1 означает,
  что запрос прошёл через цикл обработки; Result=2 — запрос просрочен и не выдан владельцу.
- PLC создаёт одноцикловый BOOL и обязательно оставляет низкий цикл между двумя
  запросами одного канала, чтобы прежние R_TRIG видели два отдельных фронта.
- Ack публикуется в конце скана по сохранённому Seq, а не по текущему входному тегу.
  Условия принятия, предупреждения и выполнение операции остаются у технологического FB.
  Получение Ack не означает успешного завершения движения или сброса ошибки.
- `udiHmiCommandClockMs` — TIME() PLC. Gateway пишет его свежепрочитанное значение
  в IssuedAt непосредственно перед Seq. PLC потребляет запрос старше 3000 мс с отказом,
  без импульса; перенос через переполнение 32-битного TIME учитывается.
- Gateway ждёт до 5000 мс после commit, не повторяет команду. Timeout означает
  неизвестный результат; после reconnect/restart занятый буфер не перезаписывается.
- Общие буферы параметров оси, ручного действия, типов, редактора магазина,
  Modbus-настроек и тестовых запросов защищены на всё время подготовки и подтверждения.
  Конкурирующий запрос получает явную ошибку, очереди отложенных движений нет.
- Cell Stop, Robot Stop, Stop обоих магазинов и Stop проверки точки используют
  собственные счётчики и не ждут блокировку чужого буфера параметров.
- Jog, heartbeat и удерживаемая отмена теста сохраняют свои уровневые контракты.
  Прямые записи старых импульсных BOOL больше не являются командным API.

Для 13 настроек действует отдельный буфер: `uiCellSettingIndex`,
`lrCellSettingRequest`, `udiCellSettingIssuedAtMs`, затем последним
`udiCellSettingCommandSeq`. PLC возвращает `udiCellSettingAckSeq` и
`uiCellSettingResult`: 1 применено, 2 запрещено, 3 недопустимое значение/индекс,
4 просрочено. Индексы 1..3 — допуски HOME X/Y/Z; 4 — скорость проверки точки;
5..13 — tRobotMove, tRobotAction, tRobotRelease, tDoorOpen, tDoorClose,
tHatchUnlock, tChuckOpen, tChuckClose, tCycleStart. TIME передаётся в миллисекундах.
Старые теги настроек публикуют только применённое состояние. Отказ формирует W28.

При обновлении необходимо синхронно обновить ST и gateway, импортировать новые
методы `ReadHmiCommands` и `IsHmiCommandFresh`, проверить публикацию новых тегов
и права символов. Старый gateway с новым PLC и новый gateway со старым PLC
несовместимы. Бинарный проект и сгенерированные XML этой правкой не редактируются.
Компиляцию, обновление символов и загрузку через CODESYS выполняет пользователь.
