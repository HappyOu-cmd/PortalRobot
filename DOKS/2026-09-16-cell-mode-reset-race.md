## Подтверждённый дефект исходников

`xCellManual` одновременно принадлежал двум писателям:

1. Gateway записывал в него запрос оператора.
2. `ReadHmiInputs` считывал запрос в `GVL_CELL_CONTROL.xManual`.
3. `PublishHmi` каждый скан записывал в тот же `xCellManual` фактический режим.

OPC-запись между пунктами 2 и 3 терялась. Это воспроизведено исполнением
фрагментов старого ST: после записи TRUE между чтением и публикацией оба
значения режима оставались FALSE.

Дополнительно `writeValue` немедленно записывал отправленное значение в
`latestValues` и отправлял snapshot браузеру. Если OPC-подписка не успела
увидеть промежуточное TRUE, обратного уведомления FALSE не возникало:
для подписки значение не менялось. HMI мог показывать ручной режим, пока PLC
оставался в автоматическом. `FB_ROBOT.xResetAllowed` требует `xHmiPermit`,
который требует фактический ручной режим; запрет распространяется через
станок на общий Reset. Повторное переключение даёт ещё одну попытку записи.

В старом `test_runner.py` этот же дефект уже был явно описан в комментарии и
обходился повторной записью режима после таймаута 750 мс. Поэтому успешная
подготовка тестов не доказывала надёжность одиночного нажатия в HMI.

Этот механизм согласуется с обоими эпизодами. Привязать конкретную потерю
записи в 15:35:04 к точному PLC-скану по старой БД нельзя.

## Исправление

- `xCellManual` — только фактический выход PLC, OPC-доступ только чтение.
- Gateway записывает отдельный `xCellManualRequest`, затем ненулевой
  `udiCellModeCommandSeq`. Буфер удерживается до `udiCellModeAckSeq`.
- PLC обрабатывает новую транзакцию после свежих входов Safety, до Motion.
  `uiCellModeResult`: 1 — применено; 2 — ручной режим запрещён работающим
  циклом; 3 — автоматический режим запрещён общей аварией.
- Ack публикуется после фактического режима. Отказ также потребляет команду:
  запрос не исполнится сам после снятия запрещающего условия.
- Один gateway допускает одного писателя канала. При timeout, неоднозначной
  ошибке записи или обнаружении незавершённой транзакции после перезапуска
  следующая команда не перезаписывает payload. Автоматических повторов нет.
- Для всех OPC-команд `writeValue` перестал выдавать отправленное значение за
  телеметрию. Статусы поступают из чтения и подписки PLC.
- В журнал добавлены подтверждённый режим, доступность общего Reset и снимки
  опубликованных ошибок/занятости/разрешений. Snapshot gateway не является
  атомарной трассой PLC, это явно описано в документации журнала.
- Runner переключает режим одной командой. Старый тест, требовавший повтора,
  заменён проверкой одного подтверждённого запроса; проверяется и отсутствие
  повторов при таймауте обратной связи.
- Для запрета Automatic при Safety добавлено W27 с эффектом `WARNING`.
  Ограничения общего сброса и `FB_ROBOT.xResetAllowed` не ослаблены.

Исправление действует при любом переключении режима, независимо от источника
аварии: патрон, люк, робот, магазин и прочие владельцы используют один канал.
Оно не является аудитом всех PLC-автоматов. В частности, некоторые настройки
(`lrSafetyHomeToleranceX/Y/Z`, `stCellMachineTimeouts`, `rPointCheckSpeedPercent`)
по-прежнему используют совмещённый вход/выход в `ReadHmiInputs`/`PublishHmi`.
Подмена их показаний gateway устранена, но для гарантированной доставки самих
настроек требуется аналогичное разделение запроса и применённого значения.
В технологические настройки эта правка не вмешивается.

## Применение и проверка в CODESYS

PLC Runtime и рабочий gateway во время расследования не перезапускались,
управляющие команды оборудованию не отправлялись. Бинарный `.project`, XML и
журнал событий вручную не изменялись. ST ещё нужно импортировать/применить
в проекте, скомпилировать и загрузить через CODESYS.

Нужно публиковать новые четыре тега канала режима и read-only `xCellManual`,
затем перезапустить gateway. Новый gateway при старом составе символов явно
отказывает в переключении; fallback на старую небезопасную запись отсутствует.

Проверка на симуляции после загрузки:

1. Повторить оба эпизода инъекции зажима, минимум несколько последовательных
   циклов. После снятия причины и одного запроса Manual дождаться его Ack;
   при остановленном оборудовании Reset должен стать разрешённым.
2. Повторить с другим источником `ROBOT_STOP`; никакого дополнительного
   Automatic → Manual для восстановления разрешения не должно требоваться.
3. Во время работающего цикла запросить Manual: Result=2, W11, режим не меняется.
   Остановить цикл: отвергнутая команда не должна исполниться сама.
4. При общей аварии запросить Automatic: Result=3, W27, остаётся Manual.
   После устранения аварии требуется новый запрос Automatic.
5. Проверить обычный Reset, ручное управление и Smoke; сверить новые события
   режима/разрешения со статусами PLC. Это ещё не выполненный прогон Runtime.
