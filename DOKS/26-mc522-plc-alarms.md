# Системные аварии MC522: gateway → PLC → HMI

Веб-сервис MC522 владеет текущим кодом CPU и ошибками модулей. Gateway читает
их, сохраняет исходное наблюдение в SQLite и передаёт в PLC через подтверждаемый
канал. `FB_CONTROLLER_DIAGNOSTICS` владеет защёлками, разрешениями сброса
и запросом `GLOBAL_STOP`. `FB_ALARM_MANAGER` публикует эти причины в обычном
журнале PLC, счётчиках, светофоре, звуковом сигнале и HMI.

## Классификация

- `00` CPU и `0` модуля — норма.
- CPU `5C` — предупреждение `WARNING`, источник 19, W1.
- CPU `5A` — состояние STOP приложения: остаётся прямым уведомлением HMI и
  наблюдением `controller:led:5A` в SQLite. В исполняющемся PLC не защёлкивается:
  вызов `FB_CONTROLLER_DIAGNOSTICS` уже означает RUN. Бит 19:24 зарезервирован
  для старой истории, номера остальных причин сохранены.
- Остальные ненулевые коды CPU и модулей — аварии `GLOBAL_STOP`.
- Неизвестные коды также аварийные; отсутствие кода не считается нормой.
- Сбои HTTP, авторизации и неполные ответы остаются предупреждениями HMI;
  они запрещают подтверждать восстановление затронутого источника.

ID прежних источников 0–18 сохранены. В конец enum добавлены 19
`CONTROLLER_CPU_1`, 20 `CONTROLLER_CPU_2`, 21 `CONTROLLER_MODULES`.
32-битные маски и формат `ST_ALARM_EVENT` сохранены. Порядок
`controllerDiagnostics.cpuAlarmCodes` в `visu/alarm-catalog.json` задаёт банк
и бит CPU: `bank = index DIV 32`, `bit = index MOD 32`. Существующие элементы,
включая `*`, нельзя переставлять; новые добавляются в конец. Причины,
полные условия сброса и сообщения — [таблица 15](15-equipment-error-reset-table.md#системные-аварии-mc522).

Модули агрегируются в PLC по категориям: конфигурация, питание, ток/температура,
оконечный модуль, канал, неизвестный код. Несколько слотов одной категории
удерживают одну PLC-аварию до восстановления всех. Точный слот и исходный код
каждого модуля остаются в наблюдении SQLite `controller:module:<slot>:<code>`
и в системной диагностике HMI.

## Подтверждённая доставка и свежесть

`GVL_HMI.stControllerWebRequest` — записываемая структура payload/commit;
`GVL_HMI.stControllerWebStatus` — результат только для чтения. Gateway пишет
payload, затем `udiSequence`, и удерживает пакет неизменным до `udiAckSeq`.
Новое наблюдение во время ожидания Ack остаётся для следующего пакета.
После разрыва повторяются прежние payload/Seq; одинаковый Ack не запускает
причину заново. Неподтверждённый пакет другого запуска не перезаписывается.

Payload содержит текущие маски и `5C`, отдельные накопленные обнаружения,
признаки валидности CPU и модулей. Шлюз проверяет возраст чтения CPU ≤10 с
и модулей ≤15 с. Перед записью читаются часы PLC `udiHmiCommandClockMs`.
PLC принимает текущую валидность при возрасте пакета ≤3 с; на каждом скане,
включая первый после STOP, проверяет возраст последнего кадра ≤12 с.
Переполнение 32-битных часов учитывается явно. Устаревшие обнаружения, кроме
состояния STOP `5A`, могут добавить аварию в историю, но не разрешают её сброс.
Текущий код `5A` в пакете не подтверждает восстановление других аварий CPU,
даже если возраст пакета допустим: требуется новый свежий код `00`/`5C`.

Очередь, неоднозначно завершённый пакет и слоты ранее аварийных модулей
сохраняются в `visu/gateway/data/controller-plc-outbox.json`, вне Git.
Файл заменяется через временный. Ошибка чтения или проверки очереди при старте
блокирует канал; повреждённый файл не затирается. При ошибке сохранения в работе
gateway повторяет сохранение не чаще раза в секунду. До успешной записи
подготовленного пакета на диск чтение/запись канала PLC остаются заблокированы.
Восстановление не меняет payload/Seq ожидающего Ack пакета и не удаляет новые
наблюдения. Сообщение HMI содержит операцию (`read`, `validate`, `write`, `rename`)
и код исходной ошибки. Неизменная очередь повторно на диск не записывается.
Не удалять его для «сброса»: он хранит недоставленные причины и подтверждения.
Отсутствующий ранее аварийный слот не подтверждает норму, в том числе после
перезапуска gateway. Нужен успешный ответ этого слота с кодом 0.

## Сброс и запрет автоматического перезапуска

Исчезновение кода само не снимает PLC-защёлку. Общий Reset требует свежего
подтверждения отсутствия всех текущих аварийных кодов затронутых источников
и готовности остальных владельцев общего сброса. `5C` не препятствует сбросу
ранее исчезнувшей аварии CPU. Потеря связи, отсутствие кода/слота и истечение
свежести снятие не подтверждают. Полученная одновременно с Reset новая причина
сначала регистрируется и не стирается этим же импульсом.

После подтверждённого исчезновения физических причин снимается вход
зависимого `GLOBAL_STOP`, чтобы робот/оси/станки разрешили собственный сброс.
Защёлки остаются: ячейка принудительно остаётся в Manual, Start/Enable
и переход в Auto запрещены до Reset. Сброс не запускает цикл. Это исключает
взаимную блокировку «сброс запрещён из-за GlobalError, GlobalError невозможно
снять без сброса».

Действующий системный Stop нельзя обойти `xManualRecoveryActive` осей.
Прямой ручной I/O прекращается при системной защёлке; новый вход запрещён до
её сброса, штатная очистка ручного слоя возвращает DO программе.

Для `5C` отдельный `xResetWarnings` действует только после свежего кода CPU,
отличного от `5C`. Общий Reset его не снимает. Остальные PLC-предупреждения
можно подтверждать независимо от активного `5C`. Индикация кнопки HMI следует
PLC-тегу `xWarningResetAllowed`; окончательная проверка находится в PLC.

В STOP или при исключении PLC не исполняет эту логику. Прямое уведомление HMI
сохранено, накопленная причина доставляется после RUN; `5A` при обработке
пакета исключается из PLC-защёлок. HMI скрывает прямой
дубликат только когда соответствующая активная авария уже есть в PLC-журнале,
а не по одному факту записи OPC UA. Останов программой PLC в момент её
собственного падения не гарантируется.

## Журнал и статистика

Источник 8 SQLite хранит наблюдения с исходными кодами и слотами:
`details.effect=PLC_DIAGNOSTIC_INPUT` для аппаратных кодов,
`HMI_NOTIFICATION` — для сбоя самой диагностики. Источник 7 хранит обычные
PLC-аварии `19:<bit>`, `20:<bit>`, `21:<bit>` и предупреждение `19:1`.
Статистика считает регистрацию PLC; исходное наблюдение не удваивает факт.
Исчезновение наблюдаемого кода в источнике 8 не означает сброс защёлки источника 7.

## Применение

1. Импортировать новые DUT `ST_CONTROLLER_WEB_REQUEST/STATUS`, FB
   `FB_CONTROLLER_DIAGNOSTICS`, обновить изменённые ST-исходники и enum.
2. В Symbol Configuration опубликовать обе структуры `GVL_HMI` целиком:
   Request — чтение/запись, Status — только чтение. Сохранить проект,
   выполнить компиляцию и загрузку через CODESYS самостоятельно.
3. Перезапустить gateway и обновить HMI. Проверить передачу и Ack в диагностике.
   Старый PLC без новых символов получает понятную ошибку канала;
   прямое уведомление HMI сохраняется.

Одного перезапуска npm недостаточно. Бинарный `.project`, сгенерированные XML
и кэш вручную не менялись. Реальные аварии в контроллере при разработке
не создавались; рабочая SQLite открывалась только для чтения.

## Локальные проверки

`npm run test:diagnostics` исполняет сетевые unit-тесты, очередь, HMI
и фактический ST нового FB в ограниченном локальном исполнителе.
Это не компиляция CODESYS и не проверка оборудования.

| Случай | Вход | Ожидаемый результат |
| --- | --- | --- |
| Защёлки | Несколько ошибок CPU/модулей, попытка Reset | Все причины остаются до свежего исчезновения и Reset |
| Потеря свежести | Невалидный/просроченный кадр либо пауза циклов | Прежняя авария сохранена, сброс запрещён |
| STOP → RUN | Обнаружен 5B, после RUN уже 00 | Причина регистрируется; не стирается Reset того же скана |
| Загрузка / STOP → RUN с 5A | Накопленный 5A либо пакет с текущим 5A, в том числе просроченный | Ack принимается, PLC-авария и зависимый GLOBAL_STOP не создаются; новый Reset/STOP/RUN не требуется |
| Прежняя защёлка 5A | В маске ранее был 19:24, рядом могут быть другие CPU/модульные причины | Снимается только бит 24; остальные причины требуют прежнего восстановления и Reset |
| 5A и настоящий отказ | В накопленных причинах 5A вместе с 5B/модульной ошибкой | Исключается только 5A; отказ регистрируется, Reset того же скана запрещён |
| Восстановление CPU при текущем 5A | Есть настоящая CPU-защёлка, получен пакет с текущим 5A | `xCpuFresh=FALSE`, сброс запрещён до нового свежего CPU 00/5C |
| Переполнение часов | Свежий пакет через границу 2³² мс | Корректный возраст |
| 5C | Reset/ResetWarnings при активном 5C, затем иной свежий код | Останова нет; снятие только отдельным ResetWarnings после исчезновения |
| Другие предупреждения | 5C и обычное предупреждение | Обычное подтверждается, 5C сохраняется |
| Seq/Ack | Смена диагностики до Ack | Старый payload неизменен; новая причина идёт следом |
| Перезапуск gateway | Сохранён пакет, Ack уже в PLC | Не повторяется новым Seq |
| Пропавший модуль | Подтверждена авария слота, перезапуск gateway, слот отсутствует | Норма не подтверждена до явного кода 0 этого слота |
| Повреждённая очередь | Некорректный JSON | Нет записей в PLC и перезаписи исходного файла |
| Ошибка сохранения очереди | Сбой записи пакета на диск, затем освобождение файла | До успешного сохранения нет OPC-записей; затем отправляется тот же payload/Seq; новые обнаружения остаются для следующего пакета |
| Постоянный файловый сбой | Ошибка остаётся на нескольких вызовах flush | Канал заблокирован, попытки сохранения не чаще раза в секунду; промежуточные вызовы не отодвигают срок повтора |
| Ошибка сохранения наблюдения | 5B обнаружен при недоступной записи, затем уже 00 | После сохранения очередь доставляет обнаруженный 5B; текущая норма передаётся отдельно от накопленной причины |
| Ошибка сохранения Ack | PLC подтвердил пакет, очистка его файла не удалась | После восстановления файл отражает Ack; подтверждённая причина не отправляется заново |
| Блокировка файла Windows | Другой процесс держит файл без разрешения замены | В диагностике `rename: EPERM/EACCES/EBUSY`, до освобождения нет записей в PLC; после освобождения тот же пакет сохраняется и отправляется |
| Неизменная очередь | Несколько одинаковых наблюдений без новых причин | Файл не перезаписывается; изменение аварийного слота сохраняется |
| HMI/каталог | Аппаратная причина зарегистрирована в PLC | Одинаковый код/причина, без двойного активного уведомления |
| Статистика | Наблюдение gateway и обычная PLC-авария | Один учтённый факт |
| Ручные обходы | Системная авария, запрос recovery осей или прямого ручного I/O | Системный Stop сохраняется; ручные DO возвращаются программе; повторный вход запрещён до Reset |
| Звуковой сигнал | Новая авария источника 22 либо предупреждение 5C источника 20 массива | Новая авария запускает звук, предупреждение не запускает |

Наборы Smoke/Regression/Generated/General ячейки не изменены.

зарегистрирован `controller:led:5A`; в 15:02:56 PLC зарегистрировал

(`observedOnConnect=true`); это время наблюдения, не точное время возникновения.

подтверждает остановку/возобновление циклов; отдельных событий снятия этих
PLC-аварий в данном фрагменте нет.

Причина в исходниках: накопленный за время загрузки код STOP доставлялся после
RUN и превращался в новую защёлку `GLOBAL_STOP`. Исправлен только
`FB_CONTROLLER_DIAGNOSTICS`: он исключает бит `5A` из прежней защёлки и новых
причин, но не использует текущий `5A` для подтверждения восстановления других
ошибок. Маски 5B, неизвестных кодов и модулей, их эффекты и условия Reset
сохранены. Имена, типы, Seq/Ack и состав OPC UA не менялись; gateway продолжает
подтверждаемую доставку старых пакетов и ведение истории STOP.

Для применения достаточно обновить `FB_CONTROLLER_DIAGNOSTICS` в CODESYS,
самостоятельно скомпилировать и загрузить PLC. Уже возникшие зависимые ошибки
других владельцев остаются до их штатного сброса; фильтр не очищает их маски.
