# Системная диагностика LicOS MC-522

Во вкладке «Диагностика → Контроллер и связь» системные показатели устройства
дополняют существующие ServerStatus OPC UA и контроль `udiPlcHeartbeat`.
Владелец системных показателей — веб-сервис самого контроллера; gateway только
читает и нормализует их. PLC, команды управления и каталог аварий не изменяются.
Основная карточка приложения показывает прямой RUN/STOP из `cpuinfo.runstate`.
Heartbeat используется отдельно для контроля выполнения циклов и существующего
допуска ручного I/O; остановившийся счётчик сам по себе не выдаётся за точный STOP.

## Проверенные источники

Проверено на реальном MC522, прошивка `V1.2.0.2`, аппаратная версия `V1.4.0.0`.
Сервис доступен на `http://<адрес PLC>:8090` и использует Basic-авторизацию.
Запросы найдены в собственном JavaScript веб-интерфейса и проверены чтением:

| GET | Поле ответа | Что показывает HMI | Опрос |
| --- | --- | --- | --- |
| `/cgi-bin/system?key=cpuinfo` | `data.cpuinfo` | Общая загрузка CPU, RAM и ROM (%); температура CPU; uptime; RUN/STOP; Debug/Release; код LED; сетевые приём/передача (КБ/с) | Каждые 3 с после завершения предыдущего опроса |
| `/cgi-bin/devinfo?key=device` | `data.device` | Модель, имя, серийный номер, производитель, версии прошивки/железа/шины/скоростного I/O, дата сборки | При подключении, затем не чаще 60 с |
| `/cgi-bin/module?key=modulemessage` | `data.modulemessage` | Слот, числовой тип и текущая ошибка каждого модуля; слот 0 — встроенный I/O | При подключении, затем не чаще 5 с |

Успешный ответ имеет `error=false`. Поле `cpu` — единственное число общей
нагрузки, оно не содержит отдельные показатели ядер. RAM/ROM также возвращаются
как проценты использования, без абсолютного размера и свободных байтов.
Объект `cpuinfo` не сообщает времена PLC-задач или историю исключений.
В опубликованном OPC UA исследованного контроллера системных показателей нет,
узел `Application.Tasks` пустой; `GlobalVars` содержит Constants и GVL_HMI.
Эти наблюдения относятся к текущей публикации символов, а не ко всем возможным
библиотекам или диагностическим интерфейсам CODESYS.

Код индикатора и его русская расшифровка берутся из таблицы обслуживания
веб-интерфейса MC522. `00` означает отсутствие ошибки; `5A` — остановленное
приложение; `5B` — исключение приложения. Неизвестный код остаётся видимым без
придуманной расшифровки. Ошибки модулей `0..5` расшифрованы по логике родного
интерфейса: норма, конфигурация, питание, ток/температура, оконечный модуль,
канал. Остальные коды показаны как коды производителя.
Это текущие состояния устройства, они не подменяют PLC-аварии ячейки.
Подробную причину исключения и полный журнал проверяют в CODESYS.

## Подключение gateway

Локальные настройки хранятся только на компьютере gateway в
`visu/gateway/data/controller-web.json`; весь каталог исключён из Git.
Пример структуры (подставить свою учётную запись):

```json
{
  "enabled": true,
  "username": "<логин веб-сервиса>",
  "password": "<пароль веб-сервиса>"
}
```

Адрес по умолчанию строится из хоста `OPCUA_ENDPOINT` и порта 8090. Для другого
адреса добавить поле `url: "http://<адрес PLC>:8090"`. Поддерживается HTTP-сервис
данной прошивки; URL не должен содержать пароль, путь или параметры запроса.
Настройки читаются при запуске gateway; после их изменения перезапустить gateway.

Переменные окружения `CONTROLLER_WEB_URL`, `CONTROLLER_WEB_USERNAME` и
`CONTROLLER_WEB_PASSWORD` переопределяют одноимённые настройки.
`CONTROLLER_WEB_ENABLED=0` либо `enabled=false` отключают опрос.
Без учётных данных запросы не выполняются: значения по умолчанию для логина и
пароля отсутствуют. В REST/WebSocket уходят только показатели, состояние связи
и адрес без учётных данных. При повреждённом файле отключается только этот опрос.

Прошивка отправляет нестандартный заголовок `Content-type text/json` без двоеточия.
Стандартные `fetch` и HTTP-парсер Node.js отвергают такой ответ. Поэтому gateway
использует отдельный ограниченный HTTP/1.0-клиент для трёх разрешённых GET:
таймаут 3 с, максимум ответа 256 КиБ, соединение закрывается после ответа.
Запросы RUN/STOP, сброса, перезагрузки, обновления и записи I/O недоступны этому
клиенту. Опрос идёт независимо от OPC UA, включая STOP приложения.

Паспорт и модули имеют отдельные даты чтения и ошибки; сбой одного запроса не
прячет успешные ответы других. При сбое чтения CPU прежние показатели очищаются.
При потере WebSocket HMI скрывает сохранённые значения всех системных карточек.
Недоступные/некорректные поля показаны как «Нет данных», а не нулём или нормой.

## Проверка

`npm run test:diagnostics` проверяет счётчик PLC и системный клиент:
реальный нестандартный заголовок, фрагментированный ответ, фиксированный GET,
401, повреждённый/неполный JSON, ограничения размера/времени, конфигурацию,
частоты опроса, отсутствие секретов в снимке, неизвестные коды, неполные поля,
частичные сбои и очистку устаревших показателей. Это unit-тесты gateway;
каталог сценариев Smoke/Regression ячейки ими не изменяется.

Для HMI выполнить `npm run build`. Проверку расположения карточек и внешний
вид вкладки пользователь выполняет самостоятельно.
