# Диагностика дискретных сигналов

В веб-визуализации: **Диагностика → Входы и выходы**. Два раздела: **Сигналы** и **Переключения I/O**. Каталог [22-physical-io-map.json](22-physical-io-map.json) содержит 84 DI и 47 DO. Фазы MPG и Home/концевики серводрайверов в каталог BOOL не входят.

## Карточки и выбор сигналов

**DO слева, DI справа**, у каждой половины своя прокрутка. Один сигнал занимает всю ширину своей половины: название и физический адрес с модулем/CH, крупные индикаторы 0/1 «Включён/Выключен», переключатель рядом. Узкая сетка карточек убрана. Верхняя панель объединяет выбор раздела и ручное управление; поиск, оборудование и выбор сигналов находятся в одной строке фильтров. Заголовок диагностики во вкладке I/O уменьшен, списки занимают оставшуюся высоту. Оформление сохраняет промышленную тему HMI.

У DI два показания: **Физический вход** и **Программное состояние** после подмены/фильтра. Физический DI имеет статус «Нет данных», пока не подтверждена карта, отсутствует модуль или связь. У четырёх DI частотников ГК технологического потребителя пока нет; они доступны для диагностики.

DO показывает окончательную команду PLC, а не подтверждённое напряжение или положение механизма. Отсутствующий модуль отмечается в карточке, но не запрещает запись программного DO. PLC-имя доступно в подсказке карточки и поиске.

**Подробнее** разворачивает тот же экран. Поиск, тип оборудования, конкретное оборудование, выбранный раздел, галочки сигналов и одна аренда управления сохраняются при разворачивании. Поиск учитывает название, PLC-имя, адрес и клемму. Есть «Только включённые», «Только выбранные», выбор по фильтру и сброс выбора. Набор различает DI:1 и DO:1. Фильтры применяются и к журналу.

## Прямое ручное управление

Общая кнопка **«Управлять сигналами вручную»** отправляет запрос входа в режим. PLC требует **Manual, явный свежий запрос и действующую аренду HMI**. Аварии, программные Busy/Processing, незавершённые команды и сырой CycleActive не запрещают передачу I/O оператору. `xIoBusy` сохраняется для диагностики и снятия отдельного программного аварийного останова; допуск входа в ручное I/O от него не зависит. Ожидающий запрос Auto завершает ручное I/O и не допускает повторного входа в том же скане.

При входе PLC запоминает фактически записанные уровни всех 47 назначенных DO из последнего завершённого скана. До первой команды каждый выход сохраняет свой уровень. Повтор запроса входа в уже активный режим не перезаписывает ручные значения. Разрешение публикуется как `xIoManualStartAllowed`, активный режим — `xIoManualControlActive`; это read-only поля GVL_HMI.

При передаче управления задания ячейки, станков и магазинов отменяются, робот получает Stop/отмену, ГК — требование восстановления. Сохраняются первичные аварии, физический груз и уже подтверждённые изменения слотов. Возврат программе не возобновляет старый рецепт: оператор проверяет состояния, выполняет необходимые подтверждения/сброс и отдельно запускает автоматику. Аппаратная цепь останова программным слоем не изменяется.

После входа **все 47 назначенных DO принадлежат прямому ручному слою**. Штатные FB продолжают рассчитывать собственные уровни отдельно, но не перезаписывают ручные. Аварии, состояние Safety, открытые двери, противоположные катушки, установленность модуля и владелец Modbus не являются условиями запрета этого слоя. Начавшееся после ручного переключения движение/обработка режим не снимает. Допустимо включить обе катушки одной пары. Пуски/сбросы удерживают выбранный уровень до переключения; автоматического ограничения 500 мс нет.

Прямое назначение выполняется в `ApplyIoOutputOverrides` в конце `WritePhysicalOutputs`. Оно намеренно действует и при неподтверждённой карте/тестовой среде; при фактическом I/O Mapping оно может записывать реальные выходы в этих состояниях. Ограничение NORMAL + `xMappingVerified` сохраняется у штатного программного слоя, а не у прямого ручного. Отсутствующие модули не могут исполнить команду электрически.

Состояния `axIoDoForceValue` хранят все ручные уровни. `axIoDoForced` и маска `adwIoForcedDo` отмечают только каналы, явно изменённые оператором для карточки/аудита; FALSE не означает, что FB может управлять каналом внутри активного режима. `adwIoDoAllowed` одинаков для всех 47 назначенных каналов и следует активному Manual I/O. Старые транспортные маски сохранены: `DoOnAllowed=DoAllowed`, `InhibitedDo=0`.

Ручное вмешательство в пневматику магазина отмечается отдельно: снимает прежнее подтверждение расстановки/Enable и меняет revision. Это учёт изменённого состояния для дальнейшей автоматической работы, а не запрет прямого DO. Штатные уровни захватов хранятся в `axIoGripperBase`, отдельно от конечных DO, чтобы ручное значение не становилось командой FB.

Кнопка **«Вернуть управление программе»**, переход в Auto, закрытие страницы или потеря её аренды снимают ручное I/O. Все DO сразу получают **текущие** уровни штатной программы; они не принудительно обнуляются и не получают старый снимок. DI-подмены снимаются до фильтрации, в том числе уже при ожидающей транзакции Auto. Восстановление связи без нового входа не включает ручной режим само собой. Если PLC позже отверг Auto, ручное I/O всё равно уже завершено.

## Подмена входов DI

В активном ручном I/O переключатель DI задаёт BOOL перед существующим фильтром переднего/заднего фронта. `Снять` или `Снять все DI` возвращает сырые входы; эти действия не завершают общий ручной режим. Установка 1 не обещает немедленный 1 после фильтра. НЗ-контакты инвертируются далее своим владельцем: подмена задаёт электрический уровень до нормализации.

В обычной ячейке подменённый DI для наладки может пройти фильтр и до подтверждения карты. Неподменённые входы сохраняют прежнюю проверку карты. Тестовые среды продолжают использовать модели оборудования; физическая подмена не заменяет их виртуальный интерфейс.

HMI использует готовые read-only допуски PLC только для приглушения кнопок. Окончательное решение принимает PLC. Отказ DI — W31, отказ входа в режим/DO — W32, эффект `WARNING`; [условия и сообщения](15-equipment-error-reset-table.md) совпадают с [каталогом предупреждений](16-cell-warnings.md) и alarm-catalog.json.

## Связь и подтверждение команд

Технические проверки транспорта сохраняются: свежесть запроса, живой HMI и аренда страницы. Страница посылает heartbeat каждые 700 мс; PLC снимает режим при потере связи, watchdog или возрасте heartbeat более 3 с. Вход в режим с просроченной арендой отклоняется. Ручные уровни, подмены и режим не RETAIN.

| Команда gateway | Action | Назначение |
| --- | ---: | --- |
| `io.override / release / releaseAll` | 1 / 2 / 3 | Установить DI / снять один / снять все DI |
| `io.output / output.release / outputs.releaseAll` | 4 / 5 / 6 | Установить DO / взять текущий программный уровень одного / всех DO |
| `io.releaseEverything` | 7 | Совместимый возврат всех DI/DO программе, завершает режим |
| `io.manual.begin` | 8 | Запомнить все DO и включить ручное управление |
| `io.manual.end` | 9 | Завершить режим и вернуть всё программе |

Действия 5/6 сохранены для совместимости API; отдельной кнопки «Снять DO» в карточке нет. Они обновляют ручный уровень из текущего штатного уровня, но не передают FB владение внутри активного режима. Индексы DI 1..84, DO 1..50 независимы от номера физической клеммы.

Gateway имеет одного писателя обычного I/O: индекс, действие, BOOL и время PLC записываются **до Seq**. Следующий payload не меняется до Ack предыдущего, включая тайм-аут. Для 7/8/9 DI/режим обрабатываются до фильтров, DO — в конце скана; Ack выдаётся после назначения DO.

Result: 1 применено, 2 запрещено, 3 неверные индекс/действие, 4 просрочено. Отказ потребляет Seq; восстановление условий не повторяет его. При старте оба канала потребляют старые Seq без исполнения. Активная тестовая сессия gateway не блокирует прямое I/O: разрешение входа остаётся за PLC; другие тестовые ограничения сохранены.

## Экстренный останов

Кнопка запуска «Экстренный останов» убрана из меню I/O. Существующий программный контракт PLC/gateway сохранён; ниже описано его поведение. Если защёлка уже активна, HMI продолжает показывать её состояние и действие «Снять останов».

Программный запрос останова использует отдельный канал `udiIoEmergencyCommandSeq/AckSeq` и не ждёт обычный I/O. Новый Stop завершает текущий ручной режим, защёлкивает `xIoEmergencyStopActive`, подавляет штатные Start/Enable/ручные движения, переводит ячейку в Manual и подаёт Stop ячейке, XYZ/группе, роботу/SC-500 и осям магазинов. Текущие DI-подмены снимаются, DO возвращаются штатным владельцам.

**После фактического останова можно снова включить прямое ручное I/O при активной защёлке Stop или аварии.** Защёлка не отменяет уже разрешённое прямое управление на каждом скане; новый отдельный Stop снова его завершает. У реальных станков отдельной физической команды CNC Stop в карте нет.

«Снять останов» — отдельное действие, которое сохраняет проверку `xIoEmergencyResetAllowed`: активная защёлка, Manual, полный останов, живая HMI и готовый Safety; в NORMAL дополнительно сырые аппаратные цепи и карта. Это условие относится к снятию программного останова, а не к прямым DO. Снятие не выдаёт Start/Enable и само не возобновляет движение. Отказ — W33. При защёлке `xAutomaticAllowed=FALSE`, запрос Auto отвергается W27 и потребляет Seq.

Останов принимается без требования свежести, чтобы задержанный Stop тоже останавливал; снятие требует свежести. При STOP приложения или потере транспорта программный запрос не исполняется. Аппаратная цепь безопасности остаётся отдельной.

## FIFO на PLC

`astIoEvent[1..100] : ST_PHYSICAL_IO_EVENT` — кольцевой массив. Новая запись заменяет самый старый слот; 100 элементов не сдвигаются на каждом переходе. `RecordIoDiagnostics` вызывается после `WritePhysicalOutputs`. Первая выборка фиксирует исходные уровни без выдуманных переходов.

Поля записи: возрастающий `udiSequence`, время `uliTimeMs`, направление (1 DI, 2 DO), индекс, вид события, старое/новое значение. Виды:

| Kind | Событие |
| ---: | --- |
| 1 | Сырой уровень DI |
| 2 | Уровень DI после подмены/фильтра |
| 3 | Записанная команда DO |
| 4 | Установка/изменение ручной подмены |
| 5 | Снятие подмены командой оператора |
| 6 | Автоматическое снятие подмены PLC |
| 7 | Установка/изменение ручного DO |
| 8 | Возврат изменённого DO оператором к текущему уровню программы |
| 9 | Возврат изменённого DO программе при выходе из Manual/потере аренды/новом Stop |

Изменение сырого и фильтрованного входа — две осмысленные записи: это позволяет видеть задержку фильтра и отличать физический контакт от программной подмены. Виды 4–6 фиксируют сам факт подмены/снятия, даже если электрический уровень не изменился. Повтор той же уже установленной подмены новых записей не создаёт. Быстрые импульсы, целиком прошедшие между PLC-сканами, этим журналом не измеряются.

Для OPC UA меняющийся слот кодируется в `GVL_HMI.asIoJournal[1..100] : STRING(96)`:

```text
Seq;elapsedMs;direction;index;kind;oldBit;newBit
```

Публикуются Head/Count/Sequence, `udiIoBootCounter` и `udiIoJournalRevision`. Revision нечётен на время всей публикации `RecordIoDiagnostics`, включая добавление записей и маски; вложенный `AppendIoEvent` не меняет внешний seqlock. Самостоятельные добавления до Record используют свой seqlock. Этот счётчик меняется на каждом скане даже без новых событий. Поэтому gateway не требует одинакового revision до и после нескольких сетевых запросов: при MainTask 4 мс прежний алгоритм постоянно перечитывал весь FIFO и отклонял результат.

С 09.10.2026 gateway каждые 200 мс читает 35 полей текущего состояния одним Read. Принятые записи FIFO сохраняются в кеше текущей OPC UA сессии; читаются только отсутствующие Seq из последних 100 записей. После получения новых строк отдельно проверяются BootCounter, Sequence и часы PLC. Рост Sequence допустим: текущий опрос возвращает проверенное окно исходного заголовка, новые события попадут в следующий. Чужой Seq в перезаписанном слоте, неверный формат или смена эпохи отвергают окно; максимум две попытки. При новом BootCounter, откате Sequence или часов прежний кеш не используется. Переполнение и пропуски по-прежнему явно фиксирует архиватор.

Без новых событий требуется один Read; при новых событиях добавляются чтение нужных строк и проверка заголовка. Повторное подключение начинает с пустого кеша, а курсор SQLite предотвращает дубли. FIFO не смешивается с обычными OPC-уведомлениями. Текущие маски и разрешения — показания для HMI с проверкой формата, без обещания единого скана для всех 35 полей; записи истории проверяются по собственным Seq и эпохе. Окончательное разрешение ручной команды всегда проверяет PLC.

Текущие уровни упакованы в `adwIoRawDi/UsedDi/ForcedDi[1..3]` и `adwIoDo[1..2]`; маски DO `adwIoDoAllowed/DoOnAllowed/ForcedDo/InhibitedDo[1..2]`. Индекс 1 соответствует биту 0 первого DWORD. Массивы DO сохраняют 50 позиций: используются 1–36 и 40–50, удалённые 37–39 всегда FALSE и не принимают команды. Эти номера не переиспользуются для сохранения смысла истории. Каталог и HMI показывают 47 DO. Индекс каталога не равен номеру физического канала; например, датчики ГК — индексы 79/80, частотники — 81..84.

Часы журнала расширяют 32-битный `TIME()` в ULINT с явной обработкой оборота примерно через 49 дней. Gateway привязывает относительное время к своим часам при первом чтении; это приближённое календарное время, а порядок переходов определяет Seq. Привязка сохраняется между опросами, поэтому изменение часов компьютера не дублирует текущий журнал. Время имеет разрешение скана PLC и точность привязки gateway. Документация: [TIME() CODESYS](https://content.helpme-codesys.com/en/CODESYS%20Development%20System/_cds_operands_functions.html), [типы времени](https://content.helpme-codesys.com/en/LibDevSummary/date_time.html).

FIFO и подмены неретентные; `udiIoBootCounter` RETAIN увеличивается при первом скане, чтобы отличать перезапуски. Переполнение счётчика Seq также открывает новую эпоху. Старые записи после старта доступны только в SQLite, если gateway успел их прочитать.

## Общий журнал

Gateway переносит новые записи в `cell-events.sqlite` как `physical-io`, со всеми именами/адресами/клеммами, видом, номером и временем PLC. Источник: станки 1–3 → 1–3, магазины/ГК → 4, захваты → 5, остальные точки → 8. Команды DI/DO, вход/выход из ручного I/O, экстренный останов и его снятие отдельно проходят обычный аудит источника 6 с аккаунтом и подтверждением PLC. Heartbeat в журнал не записывается.

Последняя архивированная позиция сохраняется в `cell_event_meta` (`io_epoch`, `io_origin`, `io_sequence`). Код записи включает эпоху, привязку времени и Seq; проверка существования кода предотвращает дубли, включая перезапуск gateway между записью события и сохранением курсора. Очистка архива сохраняет курсор и не возвращает старый FIFO в очищенный журнал.

При недоступности SQLite непрочитанная позиция не продвигается, HMI продолжает показывать PLC; gateway повторяет сохранение оставшегося буфера. Если FIFO уже перезаписан, в общем журнале появляется `physical-io-gap` с количеством потерянных записей. История более 100 записей на контроллере не восстанавливается. См. [10-cell-event-log.md](10-cell-event-log.md).

## Подключение и проверка

В существующее приложение CODESYS добавить DUT `ST_HMI/ST_PHYSICAL_IO_EVENT` и методы `PLC_PRG.ReadIoOverrides`, `AppendIoEvent`, `RecordIoDiagnostics`, **ReadIoEmergencyStop**, **ResetIoEmergencyStop**, **ApplyIoOutputOverrides**. Обновить PLC_PRG, ReadPhysicalInputs, WritePhysicalOutputs, RunSafety, RunCellControl, RunMotion, RunRobot, RunTwoPallet, RunTwoPalletAxis, GVL_HMI, FB_CELL_MANAGER, FB_TWO_PALLET и комментарий FB_ROBOT. Опубликовать новые поля GVL_HMI (включая xIoManualControlActive/xIoManualStartAllowed) и элементы массивов в Symbol Configuration, проверить права read/readwrite по атрибутам. Пересобрать/загрузить PLC самостоятельно, перезапустить приложение PLC, gateway и HMI вместе. При обновлении карты не сохранять прежний неретентный FIFO с удалёнными DO 37–39 через online change; архив SQLite сохраняется. Бинарный `.project` и сгенерированные XML этой правкой не изменены.

Локальные проверки: `npm run test:io`, `npm run test:gateway`, `npm run test:ui-state`, `npm run test:two-pallet`, `npm run build`, `node --check` изменённых модулей gateway. Каталог входных состояний/ожидаемых результатов: [20-smoke-and-integration-test-catalog.md](20-smoke-and-integration-test-catalog.md). FIFO, счётчики, часы и разрешение исполняются из ограниченного поддерживаемого ST-текста тестовым интерпретатором; это не компиляция CODESYS и не проверка физического PLC. CODESYS и браузерная визуальная сверка не запускаются; пользователь проверяет компиляцию, реальные клеммы и внешний вид на целевой HMI.
