# HMI и Three.js правила

## Область и стек

- Рабочая папка: `C:\Users\KOKSHAROV IR\Desktop\Project\Portal robot\visu`.
- Это React + TypeScript + Vite-приложение с Three.js и OPC UA gateway.
- Перед подключением библиотеки проверяй `package.json`; не устанавливай уже
  существующую зависимость повторно.
- Перед использованием меняющихся API Tailwind, Radix UI, Recharts, Iconify и
  других библиотек сверяйся с актуальной документацией.
  - Используй Context 7
- Архитектура и карта HMI-документации: [DOKS/05-architecture.md](../DOKS/05-architecture.md).

## UI и данные

- Iconify используй для промышленных и интерфейсных иконок; сначала проверь
  точный идентификатор. Не заменяй отсутствующую иконку без согласования.
- Radix UI — техническая основа диалогов, подсказок, вкладок и меню; оформление
  создавай в стиле проекта, не оставляй стандартный вид библиотеки.
- Для вариантов компонентов используй `class-variance-authority`, а классы
  собирай общим `cn()` на основе `clsx` и `tailwind-merge`.
- Tailwind CSS 4 подключай через Vite-плагин без Preflight. Не переписывай
  `theme.css` и `styles.css` без необходимости: сохраняй размеры и поведение HMI.
- Recharts применяй для статистики станков, робота, циклов, простоев и аварий;
  цвета и плотность графиков должны соответствовать токенам промышленной темы.
- shadcn/ui допускается только как техническая основа отдельного компонента.
  Не переносить его стандартный дизайн и лишние зависимости.
- Не создавать типовой нейросетевой UI с чрезмерными скруглениями, тенями,
  градиентами и пустыми карточками. Экран должен быть компактным и сенсорным.
- Компоненты получают типизированные `props`; не читать OPC UA напрямую внутри
  презентационного компонента. Сохранять существующие mapping, обработчики
  кликов, offline fallback и контракт данных.

## OPC UA

- Большие структуры/массивы подписывай целиком через доступный родительский
  MonitoredItem и разворачивай в прежние поля HMI с учётом имён CODESYS и
  IndexMin/IndexMax. Сохраняй leaf NodeId для записи команд и fallback при
  недоступном родителе; все выбранные поля должны оставаться в снимке.
- Координаты и Ack/Result обслуживай быстро, настройки и большие таблицы —
  реже; родитель наследует самый быстрый интервал своих выбранных полей.
  Проверяй фактические интервалы сервера и число MonitoredItem, а не только тегов.
- FIFO читай по новым Seq, кешируй принятые записи, проверяй эпоху/порядок и
  сбрасывай кеш при перезапуске или откате счётчиков/часов. Не требуй неизменного
  общего revision за несколько сетевых чтений, если PLC меняет его каждый скан.
- Подробности: [OPC UA](../DOKS/02-opc-ua.md) и
  [чтение I/O/FIFO](../DOKS/23-physical-io-diagnostics.md).

## Визуальная проверка

- Для приложенного референса сначала выделить размеры, отступы, типографику,
  цвета, иконки и иерархию, затем реализовать интерфейс по этим требованиям.
- Визуальный результат, включая проверку при разрешении `1920x1080`, пользователь
  оценивает самостоятельно. Не проверяй внешний вид приложения в браузере, не
  сравнивай контрольные скриншоты и не создавай их. В отчёте указывай, что
  визуальную проверку пользователь выполнит сам.
- Иконки должны совпадать по виду, размеру и толщине линий; Flaticon применять
  только при точном соответствии референсу. Не подменять показанное решение
  собственной интерпретацией без согласования.

## Three.js и анимации

- Анимация должна объяснять направление появления: нижние панели снизу,
  боковые панели со стороны края, диалоги в текущем контексте.
- Ориентир открытия `360–440 ms`, закрытия `220–280 ms`; кривые
  `cubic-bezier(.16, 1, .3, 1)` и `cubic-bezier(.32, 0, .67, 0)`, смещение обычно
  `8–20 px`, масштаб крупных панелей не ниже `0.99`.
- Не удалять элемент до окончания закрытия; высоту списков менять через
  анимируемую обёртку. Предпочитать `transform` и `opacity`, избегать тяжёлых
  фильтров во время движения 3D-сцены.
- Навигация и окна должны реагировать сразу и не зависеть от OPC UA. Частую
  телеметрию объединять с низким приоритетом, поддерживать прерывание переходов
  повторным действием и `prefers-reduced-motion`.
