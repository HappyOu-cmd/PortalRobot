# Как прикрутить логику к элементу визуализации

## Принцип разделения ответственности

React не знает NodeId OPC UA и не записывает теги напрямую. PLC не знает разметку React. Между ними работает gateway.

```text
Функциональный блок ST
  -> PLC_PRG
  -> GVL_HMI
  -> OPC UA server
  -> gateway/server.mjs
  -> src/plc/client.ts
  -> React component props
```

Обратный путь команды:

```text
Нажатие в React
  -> callback экрана
  -> WebSocket command
  -> gateway commandMap
  -> GVL_HMI command tag
  -> PLC_PRG
  -> вход функционального блока
```

## Новый статус из PLC в HMI

1. Определить владельца статуса. Внутри FB добавить его в существующую структуру `Status`, `Diag` или `Error`.
2. В `PLC_PRG.st` записать значение в соответствующее поле `GVL_HMI`. Не добавлять прямую запись из функционального блока в HMI.
3. В `GVL_HMI.gvl.st` добавить типизированное поле и атрибут публикации OPC UA: `read` для статуса, `readwrite` только если оператор должен его менять.
4. Выполнить штатный экспорт и импорт CODESYS, собрать проект и загрузить программу в PLC.
5. В `visu/gateway/server.mjs` добавить путь в `requiredSymbols`, если это обязательный статус для интерфейса.
6. В `visu/src/plc/client.ts` прочитать значение из снимка, добавить его в тип `PlcSnapshot` или доменную модель и передать дальше.
7. Передать статус через `props` в компонент. Для отсутствующих данных показывать нейтральное состояние, а не ломать экран.

## Новая команда HMI в PLC

1. Добавить команду в `GVL_HMI` как `BOOL`, `UINT`, `LREAL` или существующую структуру. Для команд срабатывающих один раз использовать импульсный `BOOL` и обрабатывать фронт в PLC.
2. В `PLC_PRG.st` явно передать её владельцу: функциональному блоку, общему управлению ячейкой или ручной команде робота.
3. В `visu/gateway/server.mjs` добавить запись в `commandMap`:

```js
'machine.enable': {
  path: 'axMachineEnable[1]',
  dataType: DataType.Boolean,
  pulse: true,
},
```

`pulse: true` необходим для одноразовой команды. Gateway сам установит бит и вернёт его в FALSE. Не разрешать браузеру передавать произвольный путь OPC UA.

4. В React вызывать команду через существующий клиент и отображать локальное состояние нажатия сразу. Открытие меню и реакция кнопки не должны ждать следующий OPC UA-снимок.
5. После ответа PLC обновление придёт как новый статус. При отказе gateway показать понятное сообщение, например «Команда не разрешена» или «Тег не опубликован».

## Важные проверки безопасности

- Разрешение команды проверяется дважды: в gateway через `commandMap` и в PLC через условия автомата состояний.
- Команда HMI не должна обходить `xManual`, `xGlobalError`, состояние механизма или блокировку безопасности.
- Для потенциально опасных действий отображать disabled-состояние до нажатия и возвращать ясную причину отказа.
- При потере OPC UA интерфейс остаётся интерактивным в локальном режиме, но не должен создавать видимость, что PLC принял команду.

## Проверка полной цепочки

1. `node --check gateway/server.mjs`.
2. `npm run build` в папке `visu`.
3. Запустить gateway и открыть `http://127.0.0.1:3001/api/health`. В массиве `missing` не должно быть нового обязательного тега.
4. Нажать кнопку один раз и проверить в watch CODESYS, что импульс пришёл, а функциональный блок обработал его по правилам состояния.
5. Проверить, что React получил итоговый статус через `GVL_HMI`, а не изменил модель навсегда только локально.
